Architecture
MXFORGE charge les structures depuis le backend (/api/structures) s'il répond ; sinon il bascule sur les métadonnées de démonstration intégrées. Démarrez le backend (node server.js) et choisissez la source dans backend/.env (demo · rest · sql).
Un navigateur ne peut pas appeler directement votre instance Maximo (blocage CORS + authentification). En production, le backend / proxy exécute ces appels et alimente MXFORGE. Voici les requêtes prêtes à l'emploi.
# Toutes les structures d'intégration publiées GET {base}/maximo/oslc/os/mxintobject?oslc.select=intobjectname,description&oslc.pageSize=200 Header: apikey: {votre_cle} # ou maxauth: base64(user:pass)
# Métadonnées : champs, types, longueur, obligatoire, domaine GET {base}/maximo/oslc/os/mxapiasset?oslc.select=*&_lid=1&_meta=1 GET {base}/maximo/api/os/mxapiasset?lean=1&oslc.pageSize=1 # échantillon
GET {base}/maximo/oslc/os/mxdomain?oslc.where=domainid="ASSETSTATUS"&oslc.select=*
Alternative directe sur la base Maximo (DB2 / Oracle / SQL Server). Ces requêtes ciblent le schéma de configuration Maximo et renvoient exactement ce dont MXFORGE a besoin.
SELECT a.objectname, a.attributename, a.title, a.maxtype, a.length, a.required, a.domainid, d.domaintype FROM maxattribute a LEFT JOIN maxdomain d ON a.domainid = d.domainid WHERE a.objectname IN ( SELECT objectname FROM maxintobjdetail WHERE intobjectname = :OBJECTSTRUCTURE ) ORDER BY a.objectname, a.attributename;
-- Synonym domains SELECT domainid, value, maxvalue, description FROM synonymdomain WHERE domainid=:DID; -- ALN domains SELECT domainid, value, description FROM alndomain WHERE domainid=:DID; -- Numeric domains SELECT domainid, value, description FROM numericdomain WHERE domainid=:DID;
SELECT intobjectname, objectname, parentobjname, relation, sequence FROM maxintobjdetail WHERE intobjectname = :OBJECTSTRUCTURE ORDER BY sequence;
Pour passer du prototype à la plateforme : ajoutez la couche backend ci-dessous. Le moteur Excel (validations, dropdowns, multi-feuilles, doc) reste identique — seule la source des métadonnées change.
┌─────────────┐ apikey/maxauth ┌──────────────────┐ métadonnées ┌─────────────┐ │ MXFORGE │ ─────────────────▶ │ Backend / Proxy │ ──────────────▶ │ IBM Maximo │ │ (ce front) │ ◀───────────────── │ (Node/Java/.NET)│ ◀────────────── │ OSLC · MIF │ └─────────────┘ JSON métadonnées └──────────────────┘ REST / SQL └─────────────┘ │ ▼ ExcelJS — génération côté navigateur .xlsx → validations · dropdowns domaines · multi-feuilles · documentation · exemples

Le backend gère : l'authentification Maximo, le contournement CORS, le cache des métadonnées, la sauvegarde et le versioning des templates, et l'export pour n'importe quel Object Structure.
